## 📌 Overview

This document captures my personal reflections on Week 7 of the DACA programme. This week was significantly more technical, as the team transitioned from SQL to Python for data analysis.

---

## 👥 Team Collaboration

### The Challenge: Python Learning Curve

Many team members were new to Python and pandas, so there was a steep learning curve. This meant balancing learning syntax with completing the analysis.

### How We Managed

We organised **pair‑programming sessions** where more experienced members helped others debug code. We also used a shared Jupyter Notebook to collaborate in real-time.

> *"Kõige raskem oli harjuda pandas'i loogikaga, aga grupi toel saime hakkama."*
> – *"The hardest part was getting used to pandas logic, but with the group's help we managed."*

### My Personal Context

**Important:** Unlike some team members who were transitioning from Power BI (Track A), I have been using Python + Plotly + Streamlit since Weeks 5 and 6 (Track B) because I'm on **Linux Mint**. Python was already my primary visualisation tool, so this week was about deepening my pandas skills rather than switching tools.

- I didn't need to "transfer" from Power BI
- I could focus on advanced visualisation and storytelling
- I helped teammates with pandas syntax and Plotly setup

## 🔍 Specific Observations

| Challenge | Impact |
| :--- | :--- |
| **New syntax** | Slower progress initially; many syntax errors for the team |
| **Understanding RFM** | Some confusion about scoring thresholds and segment definitions |
| **Virtual environment** | Gotchas with Jupyter kernel selection (venv vs system Python) |
| **Code monolith** | Single notebook with 300+ lines from four people – hard to follow initially |

---

## ✅ What Went Well

| Area | Experience |
| :--- | :--- |
| **Pair programming** | Helped everyone learn faster |
| **Visualisation quality** | Plotly graphs were clear and insightful |
| **Segmentation logic** | We agreed on a robust segment definition |
| **Team support** | Everyone contributed and helped others |

---

## 💡 Key Learnings

1. **Python is powerful but has a learning curve** – worth investing time in pandas.
2. **RFM segmentation is practical** – directly translates to business actions.
3. **Visualisation is key to storytelling** – a good plot communicates insights quickly.
4. **Collaboration on code** – using shared notebooks and version control is essential.
5. **Linux flexibility** – Using Python from Week 5 onwards gave me a head start on visualisation quality.

---

## 📝 Future Improvements

- Start Python practice earlier in the course
- Create a shared library of reusable functions for future weeks
- Use more advanced visualisation libraries (e.g., Plotly with better interactivity)
