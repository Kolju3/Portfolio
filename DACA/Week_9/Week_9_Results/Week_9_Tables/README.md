## 📋 CV Structure Table

| Section | Content | Formatting |
| :--- | :--- | :--- |
| **Header** | Name, role, email, LinkedIn, GitHub, phone | Name: 16-18pt, bold |
| **Professional Summary** | 2-3 sentences: who, what, looking for | 1 paragraph |
| **Technical Skills** | Technical, Analytics, Tools, Soft Skills | Categorized list |
| **Experience** | UrbanStyle project with quantified results | 3-5 bullet points |
| **Projects** | 2-3 GitHub projects with tech stack | Bullet points with links |
| **Education** | DACA + previous degree | Institution, year, key achievements |

## 📋 STAR Method Template

| Part | Description | Time |
| :--- | :--- | :--- |
| **S** - Situation | Context: what was happening? | ~15 sec |
| **T** - Task | Your role: what was expected of you? | ~15 sec |
| **A** - Action | What did you DO? (specific steps) | ~60 sec |
| **R** - Result | What did you ACHIEVE? (numbers!) | ~30 sec |

## 📋 Hiring Guide – Green & Red Flags (Technical Interviewer)

### Green Flags (Strong Candidate)

| Flag | Explanation |
| :--- | :--- |
| ✅ **Modular code** | Code is divided into logical functions/classes, each with one purpose |
| ✅ **Dynamic code** | Code is easily adaptable (config files, parameters) |
| ✅ **GitHub usage** | Regular commits, branches, PRs with meaningful commit messages |
| ✅ **Documentation** | READMEs, comments, clear explanations |

### Red Flags (Warning Signs)

| Flag | Explanation |
| :--- | :--- |
| ❌ **No comments** | Code lacks explanations of why or how things are done |
| ❌ **AI-generated code without understanding** | Can't explain what the code does or why it's written that way |
